# Biosaur2 v0.6.1

## Highlights

### Project feature match-between-runs

Project Hybrid mode now supports feature-only match-between-runs (MBR). Each
run first produces its own measured feature population and private weak MS1
isotope-envelope candidates. Compatible source runs are aligned by strong
features and can support a target-run weak candidate. Accepted candidates keep
the target run's MS1 coordinates and abundance: Biosaur2 does not transfer a
peptide identity or quantitative intensity from another run.

Target supports compete with deterministic decoys and are calibrated with
empirical target/decoy log-likelihood ratios, monotone binning and
deterministic two-fold cross-fitting. Independent supporting runs are combined
and filtered with `--external-q-value-max`. The default external q-value limit
is 0.10, the default maximum strong-feature overlap is 0.30, and one to four
supporting runs are used by default.

Use `--no-external-id` to disable weak-candidate collection and Project MBR.
The external q-value is independent of same-run generic target/decoy controls;
this feature does not relax ordinary strict detection or same-run association
rules.

### More compact Hybrid output

Hybrid output now separates compact linked MS2 event records from feature rows:

- `<stem>.features.<format>` contains one accepted MS1 feature per row.
- `<stem>.ms1.<format>` contains canonical MS1 `scan_id`, RT seconds and total
  intensity; it is enabled by default in Hybrid mode.
- `<stem>.ms2_events.<format>` contains feature-linked MS2 references, joined
  through `feature_idx`.
- `<stem>.identifications.<format>` contains parsed PSM and direct-assay
  fields.

Hybrid feature rows now contain `scanStart`, `scanApex` and `scanEnd`. Join
these values to `ms1.scan_id` to obtain RT seconds. The legacy-compatible
minute columns `rtStart`, `rtApex` and `rtEnd` remain available. The duplicate
public fields `rt_start_sec`, `rt_apex_sec` and `rt_end_sec` have been removed
from Hybrid features.

MS1 output defaults on in Hybrid and off in Legacy mode. `--write-ms1` and
`--no-write-ms1` explicitly override the mode default. The same contract is
available in DuckDB as an `ms1` table and is recorded in the Project run index.

### Faster and more resilient projects

- Project execution uses a bounded adaptive process manager that accounts for
  available and cgroup memory, records CPU and peak-memory observations, and
  recovers deterministically from compatible checkpoints.
- Raw MS1, strict-stage, local-candidate and feature-MBR sidecars are
  fingerprinted for safe reuse.
- Native OpenMP, BLAS, NumExpr, vecLib and Arrow pools are limited to one
  thread at CLI startup so `--workers` remains the explicit process-level CPU
  budget.
- Generic-local trace extraction and component metrics use the fixed Cython
  implementation introduced in v0.6.0.

### Packaging and mzML reliability

- Linux extension builds no longer retain absolute build-machine
  RPATH/RUNPATH entries.
- `pynumpress>=0.0.9` is now an explicit runtime dependency for mzML files
  using MS-Numpress arrays.
- Runtime metadata declares Python 3.12 support.

## Upgrade notes

- Project metadata schema advances to 12; Hybrid output schema advances to 9;
  common output schema advances to 6.0.
- Raw MS1 cache ABI advances to 2 and strict-stage cache ABI advances to 4.
  Older caches are not reused and will be rebuilt safely.
- Existing downstream consumers of Hybrid `rt_*_sec` fields should instead
  join feature scan boundaries to the MS1 table. Consumers of legacy
  `rtStart`, `rtApex` and `rtEnd` require no change.
- Existing Hybrid scripts that assume only three primary sidecars should
  account for the default MS1 sidecar, or use `--no-write-ms1`.

## Validation

- Complete unit/integration suite: `305 passed, 6 warnings` on Python 3.12.
  The warnings are known multiprocessing `fork()` deprecation warnings.
- Bundled mzML Hybrid smoke: 117 MS1 scans, 185,806 centroid points and 1,516
  strong features.
- Ten-run PXD010154 Project replay: all ten runs validated successfully;
  131,308 weak candidates were evaluated and 5,696 were accepted at the
  configured external q-value threshold.
- In the ten-run Hybrid output comparison, feature, linked-MS2,
  identification and external-evidence row counts matched the prior baseline
  for every run. Including the new MS1 lookup tables, total public output size
  decreased by 3,441,464 bytes (1.77%).
