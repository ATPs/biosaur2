# Biosaur2 v0.7.0

## Adaptive Project scheduling

Project execution now uses adaptive process scheduling that accounts for CPU
availability and memory used by each process tree. Tasks can be admitted
speculatively, paused and requeued when memory pressure requires recovery, and
tracked with heartbeat-based resource sampling. New-run memory reservations
are retained until a task has accumulated CPU time, preventing premature
admission of competing work.

Project summary generation and validation I/O now run in parallel with the
pipeline where their dependencies allow. DuckDB output staging uses bounded
per-run thread allocations, avoiding the unused default connection and hidden
native-thread oversubscription.

## Faster hybrid processing

The hybrid workflow overlaps strict-stage cache publication with hybrid
postprocessing and cancels the background cache writer cleanly when processing
fails. Candidate filtering, residual selection and peak splitting have also
been reorganized for faster single-run hybrid stages while retaining the
existing feature-detection workflow.

## Validation

- The changes include expanded coverage for adaptive scheduling, project
  workflows, hybrid stages, cache handling, DuckDB output and peak splitting.
