# Biosaur2 v0.6.2

## Flexible Hybrid PSM input

Hybrid `--psm-path` now accepts Percolator target PSM inputs in TSV (including
compressed text) and Parquet form. Parquet ingestion reads only the resolved
identification columns in batches, so pipeline-specific extra columns are
accepted without changing the compact Biosaur2 output schema.

Composite `PSMId` remains fully supported. Tables may also use split identity
columns such as `idn`, `scan_id`, `charge` and `rank`; Biosaur2 constructs a
stable audit PSM identifier when a composite ID is absent. If an input charge
is absent, a uniquely mapped mzML MS2 precursor charge can be used for the
direct assay.

When a PSM table contains several runs, rows are selected by an exact,
case-insensitive match between its run/idn value (or the parsed `PSMId` run
component) and the current mzML filename stem. This makes one aggregate PSM
Parquet usable for multiple input files while retaining same-run association
safety.

## Custom column names and Project support

Automatic semantic detection recognizes common aliases for PSM ID, run/idn,
scan, charge, rank, peptide, q-value and optional PEP, score, proteins, native
ID and decoy fields. Nonstandard names can be supplied with the advanced
`--psm-*-column` options. These options are intentionally shown only by
`biosaur2 --help-all`; `biosaur2 project run --help-all` exposes and forwards
the same mapping to every run in a Project command.

Project manifest pairing now recognizes standard Percolator target PSM/peptide
Parquet suffixes and records them as `percolator_parquet`. Existing
`percolator_tsv` manifests remain compatible.

## Validation

- Focused identification, manifest and Project tests: 18 passed.
- CLI/help and PSM reader tests: 14 passed.
- Real-world Parquet smoke: a 974,546-row Percolator table was read in batch,
  filtered to 6,735 rows for run `1554492`, accepted 761 q-filtered PSMs and
  reported zero parsing failures.
