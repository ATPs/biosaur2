# 2026-07-30 update: identification-aware residual feature detection

## Summary

This update adds an opt-in hybrid DDA workflow whose primary product is an
accurate, de-duplicated MS1 feature population with one reliable quantitative
value per accepted feature. It uses q-value-filtered direct PSMs and generic
MS2 precursor evidence to associate or recover features where scientifically
defensible, while leaving non-MS2 feature thresholds unchanged.

The current milestone target was approximately 60% aggregate quantitative
MS2-feature coverage on a frozen representative panel, subject to strict
feature preservation, positive unique quantification, intensity conservation,
target/decoy behavior and honest unresolved outcomes. The broad 12-run standard
result reached 70.5727%. A narrower guarded-relaxed four-run experiment reached
69.7888% and added 1,119 reliable links over its same-input standard baseline
without losing any standard link or baseline strict scientific row.

The hybrid workflow remains optional and default-off. The conservative relaxed
retry is a separate opt-in switch and also defaults off.

## Motivation

The earlier workflow primarily detected MS1 features first and treated MS2 as
weak downstream evidence. That left many MS2 events unmatched even when their
RT, precursor context or high-confidence PSM could help distinguish the best
MS1 representation.

The new design keeps the complete strict MS1 population as the foundation, but
adds targeted evidence and an intensity-conserving residual model so that:

- multiple MS2 events can associate with one feature without duplicating its
  abundance;
- exact identified isotope distributions can repair or recover difficult local
  features;
- unidentified MS2 events can use bounded charge/C13/averagine hypotheses;
- strict, MS2-guided and final-residual candidates can be compared locally;
- unresolved events remain auditable rather than being forced into weak
  features.

## User-visible changes

### Explicit feature modes

The single-run CLI now supports:

```text
--feature-mode legacy
--feature-mode weak-ms2
--feature-mode hybrid
```

Project execution has corresponding `--mode` values. Both CLIs default to
`legacy`; hybrid processing must be explicitly selected. The existing
`--ms2-seed` option remains an alias for weak-MS2 compatibility behavior.

q-value < 0.01. No q-value threshold was raised to improve coverage.

### Quantification methods

Hybrid mode exposes exactly three feature-level methods:

- `envelope_area`: trapezoidal area of the final assigned isotope envelope over
  real RT seconds; default;
- `mono_area`: area of the final monoisotopic contribution;
- `envelope_apex`: maximum summed assigned isotope intensity on one common MS1
  scan.

The selected value is recorded together with raw/corrected areas, quantification
status, feature origin, confidence tier, support counts and quality flags.

## Algorithm improvements

### One-pass MS1/MS2 ingestion

The reader now retains all metadata needed by residual processing:

- original MS1 centroid points and scan offsets;
- normalized RT seconds and native scan identity;
- every DDA MS2 event and resolved precursor MS1 relation;
- selected ion and isolation boundaries;
- charge, FAIMS and ion-mobility metadata where present.

The compact raw store can be memory-mapped from a cache so parameter tuning does
not repeatedly decompress and parse mzML.

### Robust Percolator and chemistry support

The update adds:

- q-value-first semantic parsing of Percolator target PSM tables;
- compression, encoding/BOM, delimiter and header handling;
- safe PSM-to-MS2 mapping by native identity or validated run/scan parsing;
- canonical modification normalization;
- a pinned local Unimod subset with no runtime network requirement;
- explicit fixed modifications;
- exact-formula, mass-only and unavailable modification states;
- sequence/formula-specific theoretical isotope libraries;
- selected C13 isotope-index evaluation.

PSMs provide strong prior evidence but cannot create a quantitative feature in
the absence of coherent MS1 chromatography.

### Residual MS1 ownership

`ResidualMS1Ledger` tracks original, assigned and remaining intensity at raw
point level. It enforces non-negative allocation, prevents over-subtraction and
provides reversible provenance. The central invariant is:

```text
claimed feature intensity + residual intensity = original MS1 intensity
```

Initial strict features claim their valid contribution first. Direct/generic
recovered features and final-residual strict features must then allocate from
the remaining signal. This prevents an MS2-supported candidate from silently
consuming an established high-quality feature.

### Direct identified feature association and recovery

Every exact direct assay first searches the strict population. Unmatched assays
can extract bounded raw MS1 isotope traces around the MS2 event. Acceptance
requires multi-scan chromatographic support, isotope evidence, mass/RT/charge
compatibility, event and isolation localization, non-conflict with strict
ownership, successful residual allocation and reliable quantification.

High-confidence direct-to-strict matches calibrate run-specific mass error,
feature width and MS2-to-apex RT behavior. One monotonic retry may use this
calibration. Repeated PSMs or MS2 events reuse the same feature.

### Losing processed-hill competitors and cache v2

The strict detector may destructively assign a hill before a direct assay is
processed. To avoid losing all information about plausible alternatives, the
new `direct_competitors.py` path captures direct-relevant candidates after
ordinary strict mass/cosine filtering and before greedy ownership.

Capture is deterministic and bounded to the best three representations per
PSM. Strict-stage cache version 2 persists the candidates. They can guide the
existing one direct retry, but cannot bypass raw extraction, monotonic evidence,
conflict, quantification, residual or conservation gates.

### Generic MS2 association and local recovery

Unidentified MS2 events now receive bounded charge and C13 isotope-offset
hypotheses with averagine-like expected distributions. Target candidates and
paired deterministic decoys are scored using m/z, RT, precursor scan, isolation,
charge, selected-isotope, event-apex, isotope count/cosine, coelution and point
support.

Generic processing first associates defensible strict features, then examines
unresolved events against raw/residual local traces. Candidate extraction and
confidence control are separate from Percolator q-values.

### Local hill repair and decomposition

The update adds bounded, reversible local actions:

- common-boundary RT splitting across isotope traces;
- merge of compatible fragments;
- short-gap/boundary extension;
- local relinking of incorrect trace relationships;
- non-negative decomposition for identifiable shared signal.

Repeated compatible MS2 events are clustered so that one feature can satisfy
several events. Different envelopes that share signal without an identifiable
joint solution remain explicit conflicts.

### Guarded relaxed MS2-only recovery

The optional relaxed round permits shorter but still multi-scan evidence and
some partial envelopes. It never applies to a feature without MS2. Generic
relaxation retains paired target/decoy control and strong isotope-fit criteria.

The first unguarded experiment found three cases where a relaxed candidate
changed a better final-residual strict representation. A same-residual strict
competitor guard was therefore added:

- an equivalent strict candidate wins when its isotope/chromatographic evidence
  is clearly superior;
- an MS2-supported candidate may win only inside the defined uncertainty margin;
- different charge/mass envelopes sharing raw points are rejected when the
  allocation is not identifiable.

The guard rejected exactly the three problematic assignments while preserving
the remaining relaxed gains.

### Final strict residual detection and MS2 recheck

After targeted recovery, the unchanged strict detector runs on remaining
residual MS1. It discovers untargeted features, including features without MS2,
using ordinary strict thresholds. Equivalent already accepted features are
de-duplicated before allocation.

Unresolved direct and generic MS2 events are then rechecked against newly found
strict features. This ordering allows targeted evidence and strict population
completeness to complement one another without lowering non-MS2 standards.

### Project manifests and external assays

Project mode adds deterministic manifest parsing, bounded per-run execution,
resume/overwrite semantics, atomic publication and a compact DuckDB status
database.

Compatible runs may be aligned using robust monotonic RT mappings built from
shared high-confidence peptide/charge anchors. External exact assays are weaker
than direct assays and use their own target/decoy control. Recipient-run MS1
signal is always extracted and quantified; donor intensity is never copied.

### Outputs and auditability

Hybrid output now contains:

```text
<stem>.features.parquet
<stem>.feature_quant.parquet
<stem>.ms2.parquet
<stem>.ms2_feature_links.parquet
<stem>.identifications.parquet
<stem>.id_assays.parquet
project.duckdb
```

There is one positive quant row per accepted feature and exactly one audit row
per MS2 event. Audit outcomes explicitly distinguish quantitative features,
insufficient chromatographic evidence, ambiguous raw-point conflict,
precursor-only signal, metadata/assay problems and statistical rejection.

## Performance and reproducibility improvements

- Raw, strict-stage and local-candidate cache layers avoid repeated mzML/hill
  work during parameter tuning.
- Cache keys include source, scientific parameters, implementation signature
  and residual ownership state where relevant.
- Atomic staging prevents partial output/cache publication.
- Deterministic ordering is used for candidates, conflicts, IDs and project
  scheduling.
- File-level `run_workers` and per-file `nprocs` are explicitly bounded;
  nested parallelism requires opt-in.
- Development validation was staged on one to four files before expansion and
  never exceeded six real mzML files per tuning experiment.

## Final decision

The approximately-60% milestone and mandatory reliability invariants are
complete. The recommended broad configuration is standard hybrid residual mode
with relaxation disabled. Guarded relaxation is available as a validated but
narrower opt-in configuration.

The remaining limitations are research directions rather than reasons to lower
standards:

- universal cross-envelope decomposition is not always identifiable;
- external assays may produce no valid recipient feature;
- processed-hill competitors may improve local evidence without surviving all
  quantitative/conflict gates;
- sparse or event-misaligned isotope traces must remain unresolved.

Future work should prioritize multi-scan trace recovery and identifiable
regional overlap models. It must continue to forbid single-scan quantitative
features, duplicated shared intensity, donor-abundance copying, relaxed non-MS2
thresholds and weakened q-value control.

For the stable algorithm description, see [`design.md`](../design.md). Detailed
development evidence remains in `.local/2026-07-29-ms2-seed.md` and
`.local/2026-07-29-target-completion-audit.md`.
