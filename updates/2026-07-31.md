# Biosaur2 0.6.1

## Project feature match-between-runs

Project Hybrid mode now performs feature-only match-between-runs (MBR). Each
run retains a private set of measured weak isotope-envelope candidates. After
strong-feature RT alignment, strong features from compatible source runs can
support those target-run candidates. Accepted rows keep target-run MS1
coordinates and abundance; Biosaur2 does not transfer peptide identity or
source-run intensity.

Target supports compete with deterministically shifted decoys. Component-level
support scores are converted to empirical target/decoy log-likelihood ratios
with monotone binning and deterministic two-fold cross-fitting. Evidence from
distinct runs is combined up to `--external-max-support-runs`, then filtered by
the independent Project `--external-q-value-max` threshold. The raw support,
calibrated contribution, target/decoy counts, q-value and alignment diagnostics
are written to `external_id_evidence`.

The default external controls are a 0.10 q-value limit, at most 0.30 same-run
strong ownership overlap, and one to four supporting runs. These defaults do
not relax ordinary strict detection or same-run generic target/decoy rules.
`--no-external-id` disables weak-candidate collection and Project MBR.

## Runtime and recovery

- Project execution uses a bounded adaptive process manager that accounts for
  available/cgroup memory and records CPU and peak-memory observations.
- Project resume uses deterministic checkpoints and compatible raw, strict,
  candidate and external feature sidecars. The current Project schema is 12,
  strict cache ABI is 4, raw MS1 cache ABI is 2, and feature-MBR sidecars are
  v3.
- CLI entry points limit OpenMP, BLAS, NumExpr, vecLib and Arrow native pools to
  one thread before numerical libraries load, so `--workers` remains the
  explicit process-level CPU budget.
- Generic-local component scoring and trace extraction retain the fixed Cython
  implementation introduced in 0.6.0.

## Output and installation corrections

Hybrid output now follows `--format` consistently for all public tables.
Parquet and TSV write feature, MS1, linked-MS2 and identification files;
DuckDB stores the corresponding four tables in one per-input database. The
MS1 table is enabled by default in Hybrid and can be suppressed with
`--no-write-ms1`.

The identification schema is unchanged. In particular,
`canonical_peptidoform` remains available alongside `peptide_raw` because it
preserves normalized and fixed modification notation needed by downstream
identity matching.

Linux extension builds strip absolute build-machine RPATH/RUNPATH entries, and
the CI workflow rejects wheels that retain such paths. `pynumpress>=0.0.9` is
now an explicit runtime dependency for mzML files containing MS-Numpress arrays.
Runtime metadata declares Python 3.12. Cython and setuptools remain declared
for users who build directly from a repository checkout; standards-based pip
and `python -m build` workflows also obtain them from `pyproject.toml`.

## Validation

- Current complete unit/integration suite: `305 passed, 6 warnings` in the
  normal conda base environment. The warnings are Python 3.12 multiprocessing
  `fork()` deprecation notices.
- The bundled mzML Hybrid smoke reads 117 MS1 scans and 185,806 centroid
  points, producing 1,516 strong features and 187 private weak candidates.
- A ten-run PXD010154 replay from compatible v3 sidecars evaluated 131,308 weak
  candidates and accepted 5,696 at the configured external q-value threshold;
  all accepted abundance remained target-run MS1 abundance.

The original same-run Hybrid milestone and its broader validation panel remain
documented in [the 0.6.0 update](2026-07-30.md).
